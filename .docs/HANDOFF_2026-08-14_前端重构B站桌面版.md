## 三、后端 API 契约（本轮唯一改动约束，务必照抄）

> 以下字段名均来自实际 Java 代码与 `@JsonIgnore` 行为，不是推测。**前端请求/字段必须与之一一对应，不得臆造字段名。**

### 3.1 响应封装

所有接口返回 JSON：

```json
{ "code": 200, "msg": "success", "data": <任意> }
```

- `code === 200` 表示成功；`data` 为业务数据。
- 错误：`code ∈ {400,401,403,404,409,500}`，`msg` 为中文提示。
- `createTime` 等时间字段序列化为 ISO-8601 字符串（`JavaTimeModule` 已禁用 timestamps），例 `2026-08-14T12:00:00`。

### 3.2 鉴权机制（关键，容易写错）

- 请求头为**自定义 `token`**（`req.getHeader("token")`），**不是** `Authorization: Bearer`。
- `LoginFilter` 校验 JWT，把 `userId` 写入 `req` attribute；`AuthFilter` 保护以下路径（无 token 返回 401「请先登录」）：
  - 前缀：`/api/upload`、`/api/admin`、`/follow`、`/like`、`/feed`
  - 精确：`/comment/add`、`/user/changePassword`、`/coupon/grab`、`/coupon/my`
  - `/api/admin/*` 额外校验 `role == 1`（管理员），非管理员 403。
- 登录返回 `data = { token, username, id }`。**当前前端只把 `token`/`username` 存 localStorage（键名 `userToken`/`username`），没有存 `id`**；个人主页是通过解码 JWT 的 `sub` 字段拿 userId（见 profile.html 的 `parseUserId`）。
- 前端遇 401 的既有约定：清 token + 跳 `login.html`。

### 3.3 字段定义（JSON 序列化后的真实字段名）

**ContentCacheDTO（列表 ContentVO 与详情 ContentDetailVO 的公共基类）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | long | 内容 id |
| authorId | long | 作者 userId |
| type | int | 1=视频，2=图文/动态 |
| title | string | 标题 |
| description | string | 简介 |
| categoryId | int | 分区（0~9，见分区表） |
| commentCount | int | 评论数 |
| likeCount | int | 点赞数 |
| authorName | string | 作者名 |
| coverUrl | string | 封面（完整可访问 URL） |
| videoUrl | string | 视频地址（**仅详情有**） |
| imageUrls | string[] | 图片列表（**仅详情有**） |
| createTime | string | 创建时间 ISO |

**ContentVO（列表）** = 上面的字段 + `isLiked`(bool) + `isFollowed`(bool)，且 `videoUrl`/`imageUrls` 被 `@JsonIgnore` **剥离**（列表拿不到视频/图片，只能用 coverUrl）。

**ContentDetailVO（详情）** = 全部字段 + `isLiked`(bool) + `isFollowed`(bool)，**包含** `videoUrl` 与 `imageUrls`。

**CommentVO / CommentCacheDTO（评论树）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| username | string | 评论人用户名 |
| commentId | long | |
| contentId | long | |
| userId | long | 评论人 id |
| content | string | 评论正文 |
| parentId | long/null | 父评论 id |
| likeCount | int | |
| children | CommentVO[] | 子评论（树形） |

**ProfileVO：** `userId`(long), `username`(string), `followerCount`(int), `followCount`(int), `isFollowed`(bool，**可为 null**), `contentPage`(PageResult\<ContentVO\>)。

**PageResult\<T\>：** `list`(T[]), `total`(int), `page`(int), `pageSize`(int), `totalPages`(int)。

**LoginVO：** `token`(string), `username`(string), `id`(long)。

**关注/粉丝列表（List\<Map\>）：** 每项键 `userId`(long)、`username`(string)、`isFollowed`(bool)、`isSelf`(bool)。

**优惠券（List\<Map\>）：** 字段名以 `CouponDao.findAvailableCoupons`（可用列表）与 `CouponDao.findOrdersByUserId`（我的券）的 SQL 别名为准；重构时**直接照抄现有 coupon.html 的字段消费**即可，勿自行改名。

## 四、字段缺口与占位策略（本轮不改后端，前端优雅降级）

B 站网页版视觉上依赖以下数据，但**当前后端没有**：

| 缺口 | B 站用法 | 本轮策略 |
|------|----------|----------|
| 播放量 viewCount | 卡片 hover 显示「▶ 播放量」 | 无则隐藏该元素；在卡片 hover 层预留 DOM 位置 |
| 弹幕数 danmakuCount | 卡片 hover 显示「▍弹幕数」 | 无则隐藏；预留 |
| 视频时长 duration | 封面右下角时长角标 | 无则不渲染角标（视频已加载时可前端读 `video.duration` 现算，可选） |
| 用户头像 avatarUrl | 圆形头像 | 无则用「用户名首字」彩色圆形占位（沿用现有逻辑） |
| 相关推荐列表 | 详情页右侧「相关推荐」 | **无推荐接口**，本轮用 `/start`（推荐流）填充右侧栏，或直接留空占位，标注 TODO |
| 直播/排行等 | 首页侧边栏 | 不实现，首页侧栏只放「分区导航」 |

**约定**：前端数据层统一从 `api.js` 返回的原始对象读取字段，未来新增字段后只需在「字段映射/兜底」处补默认值，不散落全页面。兜底写法示例：

```js
const viewCount = item.viewCount;           // undefined 则隐藏
const duration  = item.duration ?? null;
const avatar    = item.avatarUrl ?? initialAvatar(item.authorName);
```

## 六、目标文件结构（本轮要产出）

**从头再来，单页应用（SPA）**：删除现有 9 个 html，只保留一个 `index.html` 作为应用外壳；每个功能变成 `static/js/views/` 下的一个视图模块，由原生 hash 路由切换。

```
src/main/webapp/
├── index.html                 # 应用外壳：顶部导航 + 左侧抽屉 + <main> 内容容器
└── static/
    ├── css/common.css         # reset + 变量 + 布局 + 全部公共组件（卡片/按钮/toast/骨架屏/弹层）
    └── js/
        ├── main.js            # 启动：渲染外壳 + 挂载路由
        ├── router.js          # ~50 行 hash 路由（#/video/123 等），视图注册/切换/清理
        ├── api.js             # request() 封装：token 头 + 401 跳转 + {code,msg,data} 解包
        ├── auth.js            # token/username/userId 存取、parseUserId、登录态判断
        ├── utils.js           # formatTime / escapeHtml / showToast / debounce / 数字缩写(w→万)
        └── views/
            ├── home.js        # #/            首页（频道导航 + 分区 + 网格 + 关注流）
            ├── detail.js      # #/video/:id   详情（左播放器 + 右推荐 + 评论区）
            ├── search.js      # #/search?kw=  搜索
            ├── user.js        # #/user/:id    他人主页 + 我的主页合一（改密/关注粉丝/我的券）
            ├── publish.js     # #/publish     投稿（视频/图文）
            ├── login.js       # #/login       登录/注册
            ├── coupon.js      # #/coupon      优惠券中心
            └── admin.js       # #/admin       媒体运维（仅管理员）
```

**路由表**：

| 路由 | 视图 | 需要登录 |
|------|------|----------|
| `#/` | home | ✗（关注流 tab 需登录） |
| `#/video/:id` | detail | ✗（点赞/评论/关注需登录） |
| `#/search?kw=…` | search | ✗ |
| `#/user/:id` | user | ✗（本人操作需登录） |
| `#/publish` | publish | ✓ |
| `#/login` | login | ✗ |
| `#/coupon` | coupon | ✗（抢券需登录） |
| `#/admin` | admin | ✓（且需管理员） |

> 说明：
> - 选 **hash 路由**（`#/…`）而非 History API：纯 Tomcat 下 History 路由刷新会 404，hash 无需任何服务端重写，最省事。
> - 删除 9 个旧 html（`login/start/search/detail/publish/space/profile/coupon/recovery.html`）——它们已进 git、历史可找回；后端是 JSON API，不引用任何 html，删除无影响。
> - `space.html`（他人主页）与 `profile.html`（我的主页）在 B 站本是同一页，合并为 `user.js`，用「是否本人」决定展示与操作。

## 九、验收标准与验证方式

## 十、风险与注意事项

1. **接口端点名易错**：详情是 `/search/IdSearch`（**不存在 `/detail`**）；`/search/getDetailRecommended` 并非推荐列表，只是另一条详情。
2. **列表没有 videoUrl/imageUrls**（`@JsonIgnore`），首页/搜索/空间卡片只能用 `coverUrl`。
3. **鉴权头是 `token` 不是 `Authorization`**。
4. **userId 未存 localStorage**，沿用解码 JWT `sub` 的方式获取（封装进 auth.js）。
5. **布尔字段序列化为 `isLiked`/`isFollowed`**（`getIsLiked()` 的产物），且 ProfileVO 的 `isFollowed` 可能为 `null`，判断时用 `=== true`。
6. 媒体 URL（coverUrl/videoUrl/imageUrls）后端已拼好 context path，前端直接 `src=` 使用即可。
7. 媒体文件可能存在缺失（历史上发生过灾后恢复），封面/视频 `onerror` 兜底（占位首字/提示）要保留。
8. **URL 方案变更**：从 `detail.html?contentId=123` 变为 `#/video/123`；`#/` 起首页，刷新不掉状态；旧 `.html` 链接不再存在，所有页内跳转统一用 `location.hash` 或 `router.navigate()`。
9. **SPA 状态清理**：切换视图时未清理的 `setInterval`/事件监听会累积，导致重复请求或内存泄漏——每个视图模块需提供 `mount()` / `unmount()` 生命周期，router 切走时调用 `unmount()`。
