### 5.5 代码与架构（阶段三~七结论）

- Servlet 覆写不能 `throws Exception`；业务异常已收口成具体异常，ExceptionFilter 兜底。
- `ErrorCode` 是枚举，用 `BusinessException(ErrorCode,...)` / `writeError(ErrorCode,...)`。
- web.xml 已注册 ExceptionFilter→EncodingFilter→LoginFilter→AuthFilter；EncodingFilter 已去 `@WebFilter` 注解，**改 web.xml 别重复加块**。
- `/upload/*` 由 `context.xml` PostResources 提供，base 与 `app.properties` 的 `upload.path` 必须一致（启动校验），改路径两处同步。
- DAO 只接收 Connection；事务统一 `TransactionTemplate`；新增 DAO 方法不要再自取连接。
- 业务代码零 `printStackTrace`/`System.out`（`CountRepairTool` 是唯一允许的 main 运维工具）。
- **阶段五缓存重构**：缓存逻辑原样迁入 `ContentCacheManager`（含 synchronized/shuffle/addFirst/失效回填等全部细节），评论树加载一并迁入以消除与 CommentService 的循环依赖；缓存策略以代码为准，不要"优化"。
- **阶段六管理员**：`users.role`；`UserDao.getUserRole` + `UserService.isAdmin`；`AuthFilter` 对 `/api/admin/*` 每次请求查库判 role==1，非管理员 403；`GET /api/admin/media/me` 供运维页检查；`tools/admin.py --list/--promote/--demote`（数字按 userId、否则按手机号）。
- **阶段七 IoC**：`@InjectConstructor` 构造器注入优先，`@Inject` 字段注入兼容；依赖收集同时看构造器参数与字段；多个 @InjectConstructor / 依赖缺失 / 循环依赖都会启动报错。11 个服务类已全部迁移为构造器注入（`private final` 字段）。
- **阶段七生命周期**：初始化顺序 = 创建+注入 → `@PostConstruct` → `Initializable.init()`；关闭 = `Disposable.destroy()` 优先，其余 Bean 反射 `shutdown()` 兼容。`ContentCacheManager implements Initializable, Disposable`；`AppShutDownListener` 已改为 `IocContainer.getInstance().shutdown()` 统一关闭。
- **阶段七连接池**：`MyConnectionPool` 上限 `db.pool.maxSize`(20)、超时 `db.pool.timeoutMs`(5000)；满池 `MyConnectionPool.class.wait(remaining)` 等待、超时抛 SQLException、`maxSize < initSize` 启动报错；失效连接关闭后会从 `allConnections` 移除；**静态 synchronized 方法里必须写 `MyConnectionPool.class.wait/notifyAll`，裸 `wait()` 编译报错**。

### 6.1 连接池临时验证模板（上次已验证通过）

放 `D:\data\projects\VideoPlatform\stone\temp\poolcheck\`，classpath 用 `classes;mysql驱动jar`：

```java
import com.itheima.util.MyConnectionPool;
import java.sql.Connection;
import java.sql.SQLException;

public class PoolCheck {
    public static void main(String[] args) {
        try {
            Connection c1 = MyConnectionPool.getConnection();
            long start = System.currentTimeMillis();
            try {
                MyConnectionPool.getConnection(); // 满容量，应超时
                System.out.println("FAIL: second acquire should timeout");
                System.exit(1);
            } catch (SQLException e) {
                System.out.println("OK timeout: " + e.getMessage()
                        + " cost=" + (System.currentTimeMillis() - start) + "ms");
            }
            MyConnectionPool.release(c1);
            Connection c2 = MyConnectionPool.getConnection(); // 归还后应可获取
            System.out.println("OK acquire after release");
            MyConnectionPool.release(c2);
            MyConnectionPool.closePool();
            System.out.println("ALL_OK");
        } catch (Exception e) {
            e.printStackTrace();
            System.exit(1);
        }
    }
}
```

运行：`$env:DB_POOL_INITSIZE='1'; $env:DB_POOL_MAXSIZE='1'; $env:DB_POOL_TIMEOUTMS='500'; java -cp "$check;$check\classes;<mysql jar>" PoolCheck`。
