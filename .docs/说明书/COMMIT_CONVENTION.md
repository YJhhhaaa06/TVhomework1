# Commit Message 约定

> 状态：v1（2026-09-18 定稿，第六期 T1）
> 目的：消息可检索、可回溯；header 一句话说清"改了什么 / 为什么"，正文只承载 git diff **看不见**的信息（决策 / 取舍 / 验证 / 代价）。治"看似说很多又好像什么都没说"。
> 关联：沿用周期约定 C-3 / G4「commit 语义闭环」（代码 + 常青文档更新 + 任务清单勾选进同一 commit、message 带任务编号）——本文件是消息**格式**细则；"不再维护文档级变更记录、以 git 历史为准"（2026-09-18 用户拍板）由本文档正文分节承载。

---

## 一、结构

```
<type>(<scope>): <一句话主题>

<正文：固定分节，必要时才写>
```

## 二、type（必填，每 commit 恰一个）

| type | 用法 |
| ---- | ---- |
| `feat` | 新功能 / 新接口 / 对外行为变化 |
| `fix` | 修缺陷 |
| `refactor` | 重构，**行为零变化**（对外可见语义不变；若实际有变化 → 用 `feat` 或 `fix`） |
| `docs` | 文档（`.docs/`、代码注释、README 等） |
| `test` | 测试（新增 / 修改测试用例） |
| `chore` | 杂务（工具 / 配置 / 脚本 / 卫生，非业务语义改动） |
| `build` | 构建 / 依赖（pom、构建脚本） |

## 三、scope（可省略）

- **改动域**：模块名（`cache` / `follow` / `content` / `comment` / `user` / `like` / `coupon` / `upload` / `admin` / `ioc` / `tools` / `feed`）或**周期令牌**（如 `prep-0N`）；周期任务建议用周期令牌。
- **跨多域打包**（如某次提案同时动两三个域）：可省略 scope，避免堆长串。
- 纯文档且覆盖全库：可省略，直接 `docs: ...`。

## 四、header（必填）

- **≤ 40 字**；一句"改了什么 / 为什么"；读完即懂，不堆细节（细节进正文或代码）。

## 五、正文（必要才写；无必要不写）

固定分节（节可省略，顺序固定）：

| 节 | 写什么 | 什么时候必须写 |
| ---- | ---- | ---- |
| `问题:` | 代码看不出的背景 / 痛点 / 上下文（如"第四期已归档，新周期需要落位"） | 有非显然动机时 |
| `方案:` | 关键取舍、否决了什么、为什么（如"U-14 与 T7/T8 撞同一批方法故不排期"） | 有决策时 |
| `验证:` | 怎么证明改动成立（JUnit 数 / pytest 数 / 实测结果 / 运行时验证） | **凡有代码改动必须写**；纯文档批写"纯文档批，无代码改动" |
| `文档:` | 同步了哪些文档（常青 / 任务清单 / 说明书等） | 文档随 commit 变化时（C-3/G4） |

> 规则：只写 git diff 里看不出、且对后来者有价值的；代码本身能说明的一律不写；小改动干脆不写正文——**空正文好过堆字**。

## 六、任务编号

- 常规任务 commit：正文首行写 `task: prep-0N`（沿用"message 强制带任务编号"，保证 commit ↔ 任务可溯源）。
- **周期级 / 纯文档批 commit 可免任务编号**（如周期立项、模板调整）。
- 引用任务一律用 `T#`（如 T1），不用 commit scope。

## 七、示例

```text
docs(prep): 第六期杂务周期立项——TASKS 拆 T1~T9、变更纪律生效

问题: 第五期已归档，prep/next-phase 杂务周期需要需求与任务落位；
      历史 commit 与文档"变更记录"长期重复维护且无格式规范
方案: ① R-03 拍板 = T1~T6 基座 + T7~T9 主菜；U-14 与 T7/T8 撞同一批
      FollowService 方法故不排期，N10 转留池 U-15
      ② 变更纪律：删除两份模板与本档"变更记录"节——变更以 git 历史为准
验证: 纯文档批，无代码改动
文档: NEXT_CYCLE_TASKS.md(新建)、NEEDS(4.2/4.3/R-03)、UNPLANNED(U-15)、
      INDEX(第六期在办)、两份周期模板(变更记录节移除)
```

```text
fix(cache): 修正批量读降级子集 key 漏续期（task: prep-0N）

问题: getBatch 降级路径漏掉对部分 key 的 sliding-renew，长驻冷数据
      超 TTL 后被误判 fallback
方案: 将续期并入既有 pipeline；不动三态与写回语义
验证: JUnit +2（批量降级续期用例）、pytest all 130 passed
文档: CURRENT_ARCHITECTURE 6.x 更新日志、TASKS T# 执行回写
```
