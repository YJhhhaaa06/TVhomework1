### 4.1 测试体系可靠性剩余缺口（高优先级）

| 编号  | 痛点                                         | 证据/影响                                                                                                                                                                                                          | 建议方向                                                                                                     |
| --- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| N1  | **coupon 用例静默跳过，回归会漏报**                    | `pytest.skip` 约 10 处，多数因"无可用券/已抢过"跳过（test_boundary:182、test_consistency:398/413/427、test_smoke:293 等）。测试库券（coupon 6 过期 / coupon 7 有限库存）是历史数据，库存数不确定 → 优惠券相关接口回归可能**静默漏报**                                                      | 基线种子固定一张"确定有货"的券 + 一张过期券，让 skip 变必跑断言（F10 最小切片，纯测试侧，T3 思路延伸）                                         |
| N2  | **conftest 保留"B 计划"降级分支，同一套用例在不同环境测的东西不同** | ① `sample_comment_id`：基线搜索 → 首页扫描兜底；② `create_test_files`：真实媒体 → 1KB 合成媒体静默降级；③ `available_coupon_id` → None → skip。每层 fallback 都意味着"悄悄改变被测对象"，确定性差、复现难                                                                | 收紧降级分支：降级时显式警告或 fail（快速失败优于静默降级）；目标态是种子完全接管后删除兜底                                                        |
| N3  | **无覆盖率数据，测试缺口无量化依据**                        | JUnit 仅 6 文件 / pytest 104 例，但无任何"哪些 HTTP 入口/业务分支未被测试"地图。F13 只否了 ID 体系与 CI，**本机 jacoco + pytest --cov 未做** → 无法回答"改某个模块需要补哪些测试"                                                                      | 本机覆盖率地图（jacoco + pytest --cov），产出"模块-测试覆盖"，为缓存改造/feature package 提供决策依据（完工前先做）                              |

## 五、方向预告（未进入本周期候选，供后续决策）

1. **缓存改造**（技术含金量最高）：拆分 ContentCacheManager 650+ 行 god class + 统一缓存接口 + P5（likeContent 缓存更新移入事务）；F11/F12 配套。前提：先做 N3 覆盖地图明确哪些缓存行为当前无测试守卫。
2. **feature package 包结构改造**（纯 Java 重构、行为不变）：按业务拆包。**与测试的关系（用户 2026-09-06 问询结论）**：
   - JUnit：与被测类**同包跟随**（Java 标准，技术性要求，低成本机械移动）；
   - pytest：已按业务功能组织（test_admin/test_hide_content/test_edit_work...），**不强行镜像包结构**（端到端按验收行为组织），重构后 pytest 一行不该改；
   - 前置：先有覆盖地图；重构安全网 = 现有测试全绿。
