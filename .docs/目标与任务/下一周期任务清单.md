* **强制探索步骤**：动刀前先 (1) 检索 db.sql 的 coupon 表结构与 coupon 6/7 的 begin/end/stock/status，裁定"新增一张确定有货的券"还是"复用既有"；(2) 逐一确认约 10 处 skip 的触发条件（无可用券/已抢过/找不到），映射改造后各自断言形态；(3) 确认"高库存专用券 + 每用例最多抢一次（断言方向不锁精确库存）"能否全量覆盖 coupon 用例并保持 T3/F10 哲学（只读确定性参照 / 环境固定资源）；(4) 若新增券影响既有计数/列表断言 → 停决策点回写本文档再动手。
* **验收**：`rg 'skip' src/test/python` 中 coupon 相关 skip 清零（仅剩显式豁免则记录理由）；连续两次 `init_test_db` 幂等，`available_coupon_id` 必命中固定券；过期券 grab 409 用例不变；`all` 与 `junit` 通过（codex 执行，G3）。

### T2 测试/生产媒体目录隔离（F9 + N6）

* **入口线索**：`tools/run_tests.py`（`base_env()` 注入点 [L93-102]、`prepare_base()` 改写 server.xml + 回读校验模式 [L270-301]、`CATALINA_BASE/webapps/ROOT/META-INF/context.xml` 的 `/upload` 挂载 base）、`src/test/python/`（conftest / test_edit_work / test_delete_content 三处 `STONE_DIR` 默认值）、`tools/cleanup_orphan_media.py` / `tools/check_integrity.py`（`resolve_upload_root`：app.properties upload.path > TV_STONE_DIR > 默认）、`tools/tv.py`（`PROD_ONLY_CMDS` 禁 test 门禁）、`AppConfig`（`upload.path` → `UPLOAD_PATH` env 覆盖）。
* **红线边界**：不改业务代码上传/存储逻辑（AppConfig 已支持 env 覆盖，无需动 Java）；不改 run_tests 安全边界（18080 隔离 / 进程归属校验 / 强杀逻辑 / 测试库注入）；不删除生产 stone 任何文件；测试媒体目录仅测试实例使用、URL 挂载与落盘目录必须一致（防"传 A 目录取 B 目录"）。若发现不改造业务代码或安全边界就无法完成隔离 → 先向用户申请并说明理由，批准后再动手。
* **强制探索步骤**：动刀前先 (1) 确认 context.xml 挂载 base 的改写时机与回读校验（仿 server.xml 模式，含"已就绪复用不停服"场景是否也要改）；(2) 裁定测试媒体目录位置与清理策略（seed 基线内容无媒体引用 → 可考虑 start 新实例时清空重建，像测试库 init；或保留手动清理，二选一需理由）；(3) 确认 cleanup_orphan_media / check_integrity 在独立目录下的目录解析依库判定（测试库 → 测试目录；生产库 → app.properties upload.path），以及 tv.py `cleanup-orphan-media` 门禁在"共享目录前提消失"后应解禁为按库判定还是维持 prod-only；(4) 确认 N6 三处 STONE_DIR 收敛方案（统一 `from conftest import` 或各自常量 + 默认值一致 + 文档写明）；(5) 若某环节出现"半隔离中间态"（如挂载改了但注入没做）→ 停决策点回写本文档。
* **验收**：`all` 全链路后 18080 上传文件落测试媒体目录、`/upload` URL 可访问（可视化验收不断）、生产 stone 时间戳无新增；`rg 'projects/VideoPlatform/stone' src/test/python` 无测试库指向残留（生产指向仅存于 prod 判定的工具逻辑）；cleanup-orphan-media 测试库语境行为明确（解禁按库判定 或 保留 prod-only 但文档写明，探索后定）；`all` 与 `junit` 通过。
