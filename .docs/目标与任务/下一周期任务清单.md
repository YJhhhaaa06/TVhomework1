## 二、任务模板（每任务必含四要素，取代旧"改动面/验收"结构）

> 背景：旧任务细节"改动面（预估非穷尽）"是弱约束，LLM 执行时常忽略"非穷尽"标注、死守写入的清单与验收标准，不随探索动态调整。自本周期起，任务详情采用如下结构（Gemini 建议）：
>
> * **入口线索（Entry Points）**：告诉 Agent"从哪里开始看"，而非"只改哪里"。例：`排查入口：tools/run_tests*.py，以此为起始点追溯调用链。`
>
> * **红线边界（Hard Out-of-Bounds）**：比起"允许改哪里"，"禁止改哪里"更有约束力。例：`禁止修改 src/main/ 下的生产业务逻辑与数据库 Schema。`
>
> * **强制探索步骤（Exploration First）**：动刀前必须先执行"检索与确认"阶段；允许 Agent 动态调整清单，但**调整前先回写任务清单/需求文档（G5/G7），再动手**。
>
> * **验收**：以探索确认后的判定为准（动态）；回归命令固定（`python tools\run_tests_report.py all` / `junit`）。

```markdown
### T新-N 任务标题

* **入口线索**：…
* **红线边界**：（禁止…）
* **强制探索步骤**：动刀前先 (1) 检索… (2) 确认… (3) 若清单未覆盖 → 回写本文档再动手
* **验收**：…
```
