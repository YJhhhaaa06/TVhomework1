## 二、前置要求：数据库备份（强制，凡 DDL 前必做）

> 用户要求：**对数据库字段做改动前，必须先把数据库的表和建表语句导出备份。**

- 目标目录：`.docs/DBbackups/`（本阶段新增，勿删）
- 备份内容：全库建表语句（结构），建议连同数据一起备份更稳妥
- 备份方式（任选其一，推荐 1）：
  1. `mysqldump -uroot -pMySQL --skip-lock-tables TVDatabase > .docs/DBbackups/schema_YYYYMMDD_HHMMSS.sql`
  2. 逐表 `SHOW CREATE TABLE` 汇总为一个 SQL 文件
- **规则**：每个阶段涉及任何表结构改动（加列/改字段/改注释/新建表）前，先执行一次备份，文件按日期命名；
- 建议将 DBbackups 纳入 git 追踪（备份文件为纯 SQL，无敏感信息），便于阶段间结构对比与回滚——是否追踪以用户确认为准（DATABASE.md 因含密码仍保持不追踪）。

## 四、数据模型改动清单

按功能梳理第三章定案：

1. `comment.is_deleted`：语义收窄为"单条评论软删除，不可恢复"（不再承载评论区开关）。
2. `comment.parent_id`：语义调整为一律指向主楼（**楼中楼两层结构**）；存量递归树数据一次性迁移重挂（数据迁移，非 DDL，阶段一，先备份步骤 0 后执行）。
3. `content` 新增 `comment_enabled TINYINT NOT NULL DEFAULT 1 COMMENT '评论区开关: 1-开, 0-关'`（阶段二，先备份）。
4. `ContentCacheDTO` 增加 comment_enabled 字段，随 backfill/缓存刷新更新（阶段二）。
5. A2 隐藏内容的状态载体：**实现时定**——复用 is_deleted 扩展值或新增 status 字段，需在阶段五前确认（若新增字段，先备份）。
6. 暂不新增 reply_to 字段（楼中楼"回复入口仅限主楼"，@ 引用省略）；若日后支持"回复某条回复"再补（届时先备份）。

### 阶段一：C1 评论软删除 + 楼中楼改造

**0. 数据迁移（先执行阶段零备份）**
- 写 Python 脚本（遵循项目脚本规范）：把存量递归树评论的 `parent_id` 上溯重挂为所在主楼 id（一级不变），形成两级结构
- 迁移前校验：无孤儿评论；迁移后跑一致性测试

**后端：**
1. `CommentDao`：删除语义改为楼中楼规则——删**主楼**：`UPDATE comment SET is_deleted=1 WHERE comment_id=? OR parent_id=?`；删**回复**：仅 `WHERE comment_id=?`（皆软删，不可恢复）
2. `CommentService`：用户自删（校验 `userId==comment.userId`，管理员删任意评论走 `role==1` 入口）
3. 缓存结构改两层：`CommentCacheDTO.children` 移除（或平铺挂主楼）、`buildCommentTree` / `insertChildToTree` / `updateCommentLikeCountInTree` 的递归改为"按主楼聚合 + 楼内列表"；`CommentVO` 相应调整；评论查询/计数按 is_deleted 过滤
4. 写评论适配：`parentId` 语义 = 主楼 id（回复的回复也传主楼 id）；`isParentIdCorrect` 校验被回复评论属于该内容
5. 接口：用户自删 `POST /comment/delete`；管理员删 `/api/admin/comment/*`

**前端：**
6. detail.js 评论区：递归树渲染 → 楼中楼（主楼卡片 + "共 N 条回复"展开/收起列表）；回复入口仅限主楼下；自己评论显示"删除"按钮；管理员侧对应入口

- 验收：删任意回复不影响其它回复展示（无"找不到父"）；删主楼整栋楼消失；他人不可见且本人不可恢复；缓存/计数一致；管理员可删任意评论；新增评论/点赞/计数回归通过。

### 阶段二：C2 作者开关评论区

- **先备份（DDL）**：content 加 `comment_enabled`
- 后端：
  1. `ContentCacheDTO` 增加 comment_enabled；backfill/刷新读取
  2. 接口：作者本人开关自己作品的评论区（校验所有权）
  3. 评论展示逻辑复用阶段一的 is_deleted 过滤；开关为整体开关，不逐条动 is_deleted
- 前端：详情页按 comment_enabled 决定是否展示评论区入口/输入框
- 验收：关闭后评论区整体不可见/不可发；开启恢复；已软删评论不受开关影响。
  > ✅ 2026-08-28 已实现：接口 `POST /content/commentEnabled`（新增 ContentController，作者所有权校验）；add 409 / show 空门禁；创作中心「我的投稿」卡片开关按钮 + 详情页门禁展示；DDL 由用户手动备份后执行（comment_enabled TINYINT NOT NULL DEFAULT 1）。待用户在新窗口执行 `python tools\run_tests_report.py all` 验收。

### 阶段三：B1 作者换源/替换媒体

- 后端：
  1. `ContentMediaDao`（原 ContentLikeDao 中方法迁入）实现删除媒体记录：按 id / 按 contentId+type+sort（B2 共用底座）
  2. 换源：校验作者本人 → 新文件落盘 → 更新 content_media 记录（url/sort/file_exists/last_verify_time）→ 清理旧物理文件 → 缓存失效并回填
  3. 接口：`/api/upload/*` 下作者本人操作
- 前端：创作中心/详情提供"替换"入口
- 验收：替换后详情展示新源；旧文件删除；媒体审计（/api/admin/media/scan）状态正常；非作者 403。

### 阶段四：A1 删除视频/帖子（含 B2）

- 后端：
  1. `content.is_deleted=1` 软删（作者本人，校验所有权）
  2. 级联：该内容全部评论软删（`WHERE content_id=?` 一次软删，覆盖主楼与楼内回复）；content_like 删除；content_media 记录删除 + **物理文件删除**（B2，确认 upload.path）
  3. 缓存：内容缓存索引/推荐列表剔除；该内容评论缓存失效
  4. 接口：`POST /content/delete` 作者本人
- 前端：创作中心"删除"按钮
- 验收：删除后列表/搜索/详情不可见；评论/点赞/媒体记录清理；缓存一致；非作者 403；BUSINESS_FLOW 问题7 关闭。

### 阶段五：A2 隐藏/取消隐藏内容（审核下架）

- **前置确认**：状态载体（复用 is_deleted vs 新 status 字段）；若新增字段，**先备份**
- 后端：管理员入口（role==1），隐藏后前台（列表/搜索/详情）不可见，管理员可恢复；与 A1"删除"语义区分（隐藏≠删除，不清理关联数据）
- 前端：管理员入口
- 验收：隐藏后前台不可见、可恢复；不误删关联数据。

### 阶段六：A3 编辑作品信息

- 后端：
  1. `updateContentInfo` 改为作者本人可改 title/description（校验所有权）
  2. 更新后同步内容缓存；全文索引由 MySQL 自动维护（FULLTEXT 对 DML 即时生效），需回归搜索
  3. 接口：`POST /content/update` 作者本人
- 前端：创作中心"编辑"入口（标题/描述表单）
- 验收：改后详情/搜索用新标题新描述；他人不可改（403）。

## 七、风险与注意事项

1. **is_deleted 语义收窄 + 楼中楼改造是行为变更**：全量排查引用点（ContentCacheManager 评论树加载/聚合、CommentCacheDTO.children、parent_id 读写、查询过滤、点赞/计数递归遍历），避免漏改；存量数据迁移需先校验无孤儿评论。
2. **缓存一致性**：软删/开关/换源都涉及缓存失效与回填，改动后回归 `dataConsistencyTest.http` 与 pytest 一致性用例。
3. **物理文件删除**：A1/B1 涉及删除 upload.path 下文件，先确认 AppConfig 的 upload.path 配置与实际路径。
4. **全文索引**：A3 编辑后全文索引即时更新，但需验证搜索回归。
5. 每阶段完成后跑 `python tools\run_tests_report.py all`，通过后再进入下一阶段。
