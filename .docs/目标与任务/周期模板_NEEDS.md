# 下一周期需求与痛点（NEEDS 模板）

> **本文件是稳定模板**：新周期开始时，**复制本文件为 `目标与任务/NEXT_CYCLE_NEEDS.md`** 后按量填写。`<…>` 为待替换占位符；本结构与历次周期（test-hardening / test-gap-fill / package-refactor / cache-architecture / cache-hardening）逐轮校准，保持稳定。
>
> **填写顺序**：① 开头引用块（状态 / 配套 / 来源）→ ② 一结转通用约定（沿用 C-1~C-3 + 延续约定，逐条核对仍有效）→ ③ 二结转未完成需求（盘点上一周期遗留 + `UNPLANNED_ISSUES.md`）→ ④ 三结转未拍板决策 → ⑤ 四本周期痛点与方案（4.1 复查 → 4.2 方向拍板 → 4.3 范围；执行中决策/质疑回写 4.0）。随周期演进，"沿用约定"如出现不再适用项，按红线措辞约定（一①）申请调整、获准后修订本模板同步。
>
> **变更纪律（2026-09-18 用户拍板）**：本档**不设文档级"变更记录"节**——变更以 git 提交历史为准，不再在周期/模板文档里重复登记流水账（模板沿用旧版时把"变更记录"节整体删除）。
>
> 术语约定：**周期 > 任务**。本文档只回答 Why（需求与决策），How（拆任务）在 `周期模板_TASKS.md`（对应实例文档 `目标与任务/NEXT_CYCLE_TASKS.md`）。

> ① **红线措辞约定**：红线只列"明显越界"的项，作用是**防跑偏、不把执行 Agent 限制死**（不穷举做法、不做一刀切禁止）；若某条红线会阻碍正确做法（过紧 / 过窄 / 已不适用）——不允许硬扛、也不允许自行放开，**先说明理由申请调整**，获批准后按新口径动手，未获批准则维持原红线（完整表述见 `NEXT_CYCLE_TASKS.md` 二节）；
> ② **编号引用约定**：禁裸编号引用已归档周期元素，引用一律写成 `<周期>/<编号>`（如 `260913/O-5`）；裸编号仅指本文档内部定义的元素；
> ③ **技术红线**：禁 Spring/SpringBoot/MyBatis；不擅改 `@WebServlet` URL / web.xml / IoC 扫描；不为实现便利改业务逻辑语义；
> ④ **脚本规范**：脚本一律 Python；临时一次性脚本放 `temp_script/`，长期复用/自动化放 `tools/`；
> ⑤ **DDL 备份**：出现表结构改动，执行前先备份库结构与建表语句到 `.docs/DBbackups/`；
> ⑥**质疑协议（G11）**：执行 Agent 对 Why 层（需求真实性/必要性）与 How 层（任务/验收可操作性）有质疑权、亦有报告义务——四时点触发（开窗阅读 / 动手前复核 / 探索中 / 验收时）× L1~L4 分级动作，质疑记录回写 4.0，**裁决权永远在用户**（完整协议与记录格式见 `NEXT_CYCLE_TASKS.md` 二节）。
